## 四、剩余限制与建议（重要）



1. **云函数有外网，但平台反爬仍需 Cookie**：2026-09-23 实测（`GET /api/netcheck`，见下）确认 EdgeOne 云函数**可正常访问公网**（example.com / baidu.com 均 200），此前"云函数无外网"的判断已证伪。线上 `/api/search` 返回空的原因是**各平台反爬拦截（无 Cookie）**，不是网络不可达。要让线上稳定出真实数据，二选一：

* **方案 B（现在可行，推荐）**：直接在 EdgeOne 控制台或 CLI（`edgeone makers env set PC_COOKIE_JD "<cookie>" -e production`）配置各 `PC_COOKIE_*` 环境变量即可，无需改代码。已实测云端无 Cookie 时 Amazon 偶发可出数据（约 4 条，不稳定），其余平台全部被拦；注入 Cookie 后按各源"所需 Cookie"列逐个放行。

* **方案 A（备选，免费）**：在一台免费可出网的云服务器（如 GitHub Codespaces / 免费 VPS）上跑 `python server.py`，把前端的 `/api/search` 指向该地址，并在该机器上 `setx PC_COOKIE_JD "..."` 等注入各平台 Cookie。

1. **纯标准库抓不动强 JS 渲染站**：表中标注 "需浏览器自动化" 的平台（得物 / 严选 / 有品 / 抖音 / 快手 / 盒马 / Temu/Shopee 等）要出数据，建议后续引入 Playwright 渲染层（在新源类里调用，保持 BaseSource 接口不变），或改用各平台开放 API。

2. **Cookie 注入方式**：本机调试 `$env:PC_COOKIE_JD="pin=...; ..."` 后 `python cli.py search 蓝牙耳机`；生产用环境变量。

3. **合规边界**：仅用公开网页端点 + 标准 UA，未做验证码破解 / 代理池 / 模拟点击；被拦截即如实返回空。
